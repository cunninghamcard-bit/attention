# Research result

**Status: Partial**

Kero's changes in this range belong in attention's appearance system only where they land on objects the v1 decision already allows. The pass makes a named light/dark theme color the whole window, and it retunes the session sidebar, the right-hand files list, and the scrollbars. Native attention still applies only `theme.For(dark, "default")` and a ribbon toggle: one flat Amp theme whose scheme changes the accent family alone, while the decision already specifies a name or a light/dark pair, icon themes, file-tree density, and theme-driven metrics, and refuses a new color-token format. In v1, adopt separate light and dark theme rows, the editor's pointer-hover scrollbar, and light/dark file-type icons; do not adopt Ghostty themes, terminal color washes, hue-tinted program colors, or the session sidebar; leave the Files tab, change letters, the narrow-window sidebar, and pane hairlines out of this appearance decision.

### What changed

The recorded changes run from session-row density, through a whole-window theme and a named light/dark default, to the right sidebar's contents and when it hides, and end on one scrollbar treatment.

### How a theme is built, versus attention

Each of those names is a wash. The config id `rex` is exposed as petal. A wash stores light and dark gradient stops, glow colors, and a tone of hue, tint, vividness, and accent hue, and a light look and a dark look are built from those stops. [S7] Light and dark are stored as separate settings, both defaulting to that starting theme. The `theme` key writes one shared name when they match, and a light/dark pair when they do not; each name is resolved to a look. [S8] The Appearance page draws the light windows, then the dark windows, with one tile per named theme, and a click writes that theme's config name into the light or dark slot. Its Ghostty popup is None plus the Ghostty theme list; a Kero theme displays as None, and choosing None restores the default theme. [S9] On a light palette a pane card is flat: a 0.5 border at about 10.6% black and a 0.5 inset at about 6.3% black, with no drop shadow. In the dark the card is raised, a lit edge plus a shadow. [S10] Program colors lean into the theme: each of the six ANSI hues is moved partway toward the tone's hue, and chroma is scaled by the tone's vividness, so nearer hues are more vivid. [S11]

The attention decision, dated 2026-11-01, is not yet followed in code. v1 only restores settings the original app can already paint, and it maps Zed ideas only onto theme objects mygo and attention-ui already have. [S18] That restore keeps system, moonstone, and obsidian plus the ribbon toggle; stores accent as one color used when painting, not as CSS variables; adds UI, body, and monospace fonts with a base size limited to 10–30 and defaulting to 16; and adds two switches, view header on by default and inline title off by default. [S19] The Zed mapping locks three font layers (UI, editor, and terminal, each with family and size), editor line height at 1.618, 1.3, or a custom ratio, a theme that is either a name or `{mode, light, dark}` with preview-before-confirm, separate light and dark icon-theme names, theme-driven syntax such as italic comments, comfortable or standard file-tree spacing, and separate switches for the tab bar, file-type icons, line numbers, and the scrollbar. Spacing, radius, and scrollbar width come from `ui.Theme` instead of fixed 8, 8, and 4. [S20] v1 excludes community CSS themes, a theme directory, Manage, CSS snippets, zoom, the native menu, window borders, custom icons, translucency, hardware acceleration, choosing which actions sit on the ribbon, and any new color-token format. `theme.For`'s scheme name stays `"default"` until a real selector writes another value. [S21]

`theme.For(dark, scheme)` builds one Amp theme-1 `ui.Theme`. The scheme changes only the accent family; `"default"` and any unknown scheme use the flat Amp primary. Paint fixes radius 8, spacing 8, scrollbar width 4, and font size 14, and leaves the font unset. The layout calls `theme.For` only as `theme.For(dark, "default")`, caches by the dark flag, and the view only applies that theme with `c.SetTheme`. [S22] The native Appearance tab exposes only the base color scheme (system, moonstone, obsidian) and Show ribbon. The window column uses the theme background; the ribbon, both docks, and the status bar use the surface color. The text editor is created without an editor theme, so a nil theme resolves to the default, whose code colors are GitHub's and whose comment token is not italic. [S23]

### Sidebar, files, and scrollbars

A detailed session row is 48px. Compact is one 34px line, and only a non-default branch is shown beside the name, ellipsized within 24–120px. [S12] The Files list is rooted at the focused pane's git worktree, otherwise that pane's process directory or directory, one folder at a time. Unfolding a folder lists it; clicking a file opens that file's text in the viewer. [S13] If the window, minus the left sidebar and the right sidebar's width, leaves under 420px for the cards, the right sidebar stays hidden until the window widens, unless the user shows it anyway. Showing it while crowded forces it on, and widening clears that force. [S14] Files and folders use Pierre's VS Code-style icon theme: a file matches its lowercase name, else its longest extension, else the theme's file icon; a folder matches its name, else the open or closed folder icon. The icons are embedded light or dark SVGs drawn at 16×16. [S15] Each changed file shows a letter at the right of the row: A added, D deleted, R renamed, T type change, and M for every other status, colored with the diff added, removed, or modified color. A deleted file's name is muted. [S16] The file viewer is mygo's `editor.View`. In the mygo revision Kero pins, the scrollbar thumb is drawn only while the pointer is inside the editor, or while a thumb is dragged; change, match, and diagnostic marks on the bar stay visible either way. [S17]

### What v1 should take

The split below is the recommendation. It does not add a finding.

Adopt in v1, on objects the decision already has. Keep a theme as a name or a light/dark pair, and show light and dark choices as separate rows drawn in their own colors. Keep preview-before-confirm; do not copy click-to-store, the wash catalog, or the starting wash as attention's default. Let the selector write the existing scheme off `"default"`, and do not add a wash or hue-tone format. Take scrollbar width from the theme, and use the pointer-hover thumb already implemented in the pinned mygo editor, with the marks left visible, instead of a second show-while-scrolling policy. When file-type icons land, use the locked light and dark icon-theme names with that matching order—lowercase name, else longest extension, else the default—as 16×16 light and dark art. That is the file-type-icon switch, not the excluded desktop custom-icon control. Also finish the decision's own sequence: one theme should color editor text and the single accent together with the chrome. Today the window and chrome take background and surface, and editor syntax stays on GitHub colors.

Wait, outside this appearance pass. The light-pane hairline versus a dark raised shadow is a concrete chrome rule, but it is defined for pane cards and is not a current `ui.Theme` field. The Files tab, the changed-file letters, and the 420px yield are worktree and layout behavior, not appearance tokens. Compact versus two-line session rows should not be copied as 48px and 34px metrics; the reader-side density control is already comfortable versus standard file-tree spacing.

Do not fit a reader. Ghostty themes, coloring terminal panes and their program colors, and tinting ANSI hues toward a theme hue are terminal-theme machinery. The session sidebar—program message, else branch and changes, else folder—is a terminal session list, not a reader surface.
