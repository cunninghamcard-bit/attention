# Research result

**Status: Partial**

Attention should look finished by exposing a few layers the widgets already paint—base scheme, accent, type, metrics, editor, and chrome—not by importing Zed's theme schema or a token list nothing reads. Beyond color, Zed specifies three font stacks and line height, gutter and indent geometry, scrollbar and minimap behavior, file-tree density, and a large chrome-visibility set, then pairs a light theme with a dark theme and ships icon themes separately. On feat/native-reader the Appearance page only sets a base scheme and a ribbon switch, while accent names, fonts, spacing, radius, scrollbar, gutter, active line, and syntax styles are already implemented and should be the first settings. Icon themes, the minimap, a token inspector, CSS snippets, and zoom stay out of scope until a widget consumes them.

### What Zed specifies besides color

Editor text, interface elements, and the terminal are three stacks—buffer, UI, and terminal—each with a family and fallbacks; the documented sizes are 14, 16, and 14, and buffer line height is "comfortable" at 1.618 (the default), "standard" at 1.3, or a custom ratio such as {"custom": 1.5}. [S2] UI and buffer weights are CSS units from 100 to 900, comments name ".SystemUIFont" or ".ZedSans" (currently IBM Plex) and ".ZedMono" (currently Lilex), and the terminal examples are an empty family at size 15 with line height "standard", and "Fira Code" at size 15, weight 400, and "comfortable". [S1]

Non-color gutter settings are line numbers, runnables, breakpoints, folds, a minimum number of line-number digits, and a separate relative-line-numbers switch. Indent guides add an enabled flag plus line width and active-line width, each in pixels from 1 to 10. [S3] The editor scrollbar chooses show as auto, system, always, or never, and can mark cursors, git diff, search results, selected text, selected symbol, and diagnostics on the horizontal and vertical axes. The minimap chooses show (auto, always, never), which editors display it (active editor or all), thumb (always or hover), thumb border (left open, right open, full, or none), a maximum width in columns, and current-line highlight (none, line, or gutter). [S4]

Chrome is a set of visibility flags: the tab bar, its history buttons, and its new, split, and zoom buttons; tab close position (left, right, or hidden), close button (hover, always, or hidden), and file icons; status-bar language, cursor position, line endings, encoding, and pending keystrokes (defaults on, on, off, non-UTF-8 only, and on) plus a short or long line indicator ("2 s, 15 l, 32 c" versus "2 selections, 15 lines, 32 characters"); title-bar branch icon and name, worktree name, project items, onboarding banner, user picture, user menu, sign-in, menus, and open-on-hover; and toolbar breadcrumbs, quick actions, selections menu, agent review, and code actions. [S5] Project-panel density is entry spacing of comfortable or standard and an indent width in pixels (the example is 20). The Appearance overview only summarizes that chrome—tab bar, navigation, file icons, and git status; status-bar language, cursor, and line endings; scrollbar visibility, git diff, and search results; a minimap; gutter line numbers, folds, and breakpoints; and Project, Terminal, and Agent panel size and docking—and points to those settings for the keys. [S6]

An extension color theme is a family with a name, an author, and a themes array; each theme has a name and an appearance of light or dark, and the file follows the themes v0.2.0 schema. [S7] Light and dark stay separate themes; mode is system, light, or dark, and the documented defaults are One Light and One Dark. [S8] Overrides are now keyed by theme name and apply only to that theme—the One Dark example sets editor background, italic comment and comment.doc syntax, and an accents list—whereas the 2024 preview stored light and dark variants in one file under ~/.config/zed/themes and applied experimental.theme_overrides to every theme, live-reloading on change. [S9][S11] Icon themes are a separate package: JSON under icon_themes, assets under icons, an appearance on each theme, paths relative to the extension root, and schema icon_themes v0.3.0. [S10] A theme builder adds a live preview, a right-click inspector that names the tokens on an element, export as overrides or an extension file, and saved families that each keep light and dark variants. [S12]

### What attention already computes

The worktree that contains the native layout plugin is on branch feat/native-reader. [S13] The Appearance view draws a base color scheme and then an Interface group whose only control is Show ribbon; the registered section is id "appearance", title "Appearance", with those labels as its keywords. [S14][S18] Base color scheme is a select on the Appearance key "theme" with system ("Adapt to system"), moonstone ("Light"), and obsidian ("Dark"); Show ribbon is a switch on "showRibbon"; the view comment says accent color, fonts, zoom, themes, and CSS snippets are not ported. [S15][S16][S17]

theme.For already accepts accent schemes default, ocean, forest, rose, and amber, and those names change only the accent family, but neither the web nor the native base-scheme control offers them. [S19] ui.Theme already has Spacing, Radius, Scrollbar, and ScrollbarWidth, and paint sets them to 8, 8, BorderStrong, and 4, with no spacing, radius, or scrollbar control on either Appearance surface. [S20] Font and FontSize exist, paint sets FontSize to 14 and leaves Font empty (the system font), and TitleFont and MonoFont are defined, but the native page does not show them; the TypeScript Appearance tab does show Interface font, Text font, Monospace font, and a font-size slider from 10 to 30. [S21] editor.Theme already colors the gutter and the caret line (LineNumber, ActiveLineNumber, ActiveLine); native editors leave State.Theme nil, so DefaultTheme supplies TextMuted at alpha 0.75, Text, and a white 0.045 or black 0.035 active line, and settings expose none of that. [S22] Token styles already carry color, bold, and italic, and DefaultTheme hardcodes a GitHub palette—TokenKeyword is #ff7b72 in the dark theme and #cf222e in the light theme, the same colors mygo v0.6.4 ships and attention-ui-pin requires—with TokenHeading and TokenStrong bold and TokenEmphasis italic, and no settings surface exposes them. [S23]

### Recommendation

This is a proposed system, not a description of the current tree.

**Layers.** Six layers, each named for a struct or control that already exists. Scheme is the light/dark pair already stored as system, moonstone, and obsidian. Accent is theme.For's named family (default, ocean, forest, rose, amber), not a free accent color. Type is the three families the TypeScript tab already edits, stored on Font, TitleFont, MonoFont, and FontSize. Metrics is Spacing, Radius, and ScrollbarWidth. Editor is one editor.Theme—gutter, active line, and tokens—selected as a whole, with DefaultTheme remaining the paint source. Chrome is visibility of elements the shell actually draws; today that is the ribbon.

**v1 settings.** Keep "theme" and "showRibbon". Add one accent select limited to those five scheme names. Port the TypeScript controls—Interface font, Text font, Monospace font, and font size 10–30—onto the native Appearance page and into those font fields. Add spacing, radius, and scrollbar width, seeded at the values paint already uses: 8, 8, and 4. Do not add a per-token syntax form, a gutter-color form, or a second editor theme until there is another concrete theme to choose.

**Do not copy yet.** Skip Zed's font fallbacks, CSS weights, named line-height ratios, and terminal font block; the local theme types that were read have no fields for them. Skip the gutter flag set, indent-guide widths, scrollbar markers, the whole minimap, and the tab, status, title, and toolbar flag matrix. Skip icon-theme packages, extension theme files, the theme builder and its inspector, CSS snippets, and zoom. When a real second theme exists, copy today's per-theme overrides, not the 2024 overrides that applied to every theme.

**Build order.** First port the three font pickers and the size slider to native and wire them to Font, TitleFont, MonoFont, and FontSize. Second, add the accent scheme next to the existing base scheme. Third, expose spacing, radius, and scrollbar width at 8, 8, and 4. Fourth, leave gutter, active line, and syntax on DefaultTheme. Fifth, add a chrome flag only when a drawn widget reads it; the ribbon is already done. Sixth, introduce a light/dark theme family with per-theme overrides only after those layers are live. Icon themes, minimap, terminal typography, and a token inspector come after that, if a widget needs them.
