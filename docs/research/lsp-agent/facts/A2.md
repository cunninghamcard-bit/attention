## glancer-arch：rust-glancer: architecture and feature coverage

**问题**：What rust-glancer is, how it is built (crates, analysis approach), exact list of LSP methods it implements (read the capabilities it advertises), memory design and claims.

**摘要**：rust-glancer 是一个实验性的 Rust LSP 实现（Rust 写的），定位是"内存占用极低、编辑器重启近乎瞬时"，README 自称目标是"90% 完整、足够日常使用，但不是 rust-analyzer 2.0"。架构核心是"冻结式（frozen）工作区"：eager 索引后把各 package 的分析结果落盘（offload），查询时按 package 只加载当次事务所需部分，事务结束即释放。LSP 服务器是编排层，每个 workspace 对应一个 engine 子进程，经 tarpc 通信，engine 只向服务器发通知。能力声明覆盖 definition/typeDefinition/implementation/references/rename(含 prepareRename)/documentHighlight/hover/documentSymbol/workspaceSymbol/foldingRange/semanticTokens(full+range)/inlayHint，并额外宣称 completion、codeAction、formatting（rustfmt 外部进程）。未声明 callHierarchy、typeHierarchy、signatureHelp、pull diagnostics；诊断通过 publishDiagnostics 推送且默认关闭。内存claim 是 idle RSS <100MB（设计目标/宣传语，文档中没有可复现的基准表）。

## ra-footprint：rust-analyzer: memory/CPU footprint and how to reduce it

**问题**：Published RSS/indexing numbers on real projects; config knobs that cut cost: cargo.buildScripts.enable, procMacro.enable, cachePriming.enable, lru.capacity, numThreads, files.exclude, check.workspace; what each disables for reading.

**摘要**：rust-analyzer 的内存占用主要来自 cachePriming（启动时预热全工程与依赖的缓存）和 salsa 缓存本身。公开数字多为用户报告而非基准测试：大型工作区 RSS 从 5–6 GB 到 40+ GB 不等，salsa 迁移后曾膨胀到约 22–30 GB，关闭 cachePriming 后降到 5.5 GiB。源码层面，buildScripts.enable 不能独立关闭：只要 procMacro.enable 为真，build scripts 仍会运行。对阅读型产品而言，关闭 cachePriming、cargo.autoreload 与 checkOnSave 可以显著降低 RSS，代价是首次跳转和符号搜索变慢，直到索引建立。files.exclude 与 check.workspace 的内存收益没有公开测量。

## rust-std：Navigating into std and dependencies

**问题**：Go to definition into std (rust-src rustup component, sysroot discovery), into dependency sources in ~/.cargo/registry/src and git checkouts; read-only handling of those files; how rust-glancer handles std.

**摘要**：rust-analyzer 用 `rustc --print sysroot`（经 toolchain 选择）定位 sysroot，再从 `lib/rustlib/src/rust/library` 取源码；若 RUST_SRC_PATH 有效则优先使用，缺失时会自动执行 `rustup component add rust-src` 再重试。源码库以只读 library source root 形式接入：不写入 VFS、didOpen/didChange 对库文件不覆盖磁盘内容，跨库编辑带 outside-workspace 注解。rust-glancer 同样用 `rustc --print sysroot` 发现，但只要求 core/alloc/std/proc_macro 四个 crate 的 lib.rs 完整存在，缺失时不自动安装 rust-src，只报错并提示 `rustup component add rust-src`，LSP 继续运行但无 std 导航。依赖源码（registry/git）两者都经 cargo metadata 得到绝对路径并作为非 workspace 包处理；rust-glancer 对依赖只做语义分析不索引函数体，导航结果走“已保存源码”读取路径，不打开或写回依赖文件。该主题对 Acard 的含义是：跳入 std/依赖应是只读库根，阅读器不应自动安装组件或改写这些文件。
