## ty-env：ty: Python environment and config discovery

**问题**：How ty finds the interpreter and site-packages (VIRTUAL_ENV, .venv, uv, conda, python-version), [tool.ty] / ty.toml config, search paths, vendored typeshed, editable installs; LSP initializationOptions/settings it reads.

**摘要**：ty 的环境与配置发现由三层组成：Python 环境（VIRTUAL_ENV → CONDA_PREFIX 子环境 → 项目 .venv → base conda → PATH 上的 python3/python）、配置文件（沿祖先目录向上找 ty.toml / pyproject.toml 的 [tool.ty]，用户级 ~/.config/ty/ty.toml 合并）、模块搜索路径（extra-paths、PYTHONPATH、first-party src roots、stdlib（自定义 typeshed 或内嵌 typeshed zip）、site-packages 及其 .pth 可编辑安装）。Python 版本按 environment.python-version → requires-python 下界 → 环境元数据/site-packages 布局推断 → 默认 PY315 依次决定。LSP 侧 initializationOptions 只是初始化参数（logLevel/logFile/untrustedWorkspace 与 ClientOptions 平铺），动态设置通过 workspace/configuration 获取；编辑器 Python 扩展选中的解释器只作为 fallback。文档 python-version.md 写 fallback 为 3.14，代码为 PY315，属于文档过期。

1. [fact/high] Python 环境发现优先级：VIRTUAL_ENV（非空即独占，解析失败直接返回错误不再回退）→ 子 Conda/Pixi 环境（含 python）→ 项目根 .venv（失败则继续）→ base Conda → PATH 上 python3 再 python。  
   来源：~/Projects/lsp-ref/ruff/crates/ty_site_packages/src/lib.rs:310-355 (PythonEnvironment::discover, 注释与分支); ~/Projects/lsp-ref/ty/docs/modules.md ('Python environment' 节)
2. [fact/high] VIRTUAL_ENV 与 CONDA_PREFIX 仅在非空时生效；.venv 候选仅在传入 project_root 时产生；路径可以不存在，由 discover 解析。

**摘要**：basedpyright 是 pyright 的 fork（本地 package.json 基线 1.1.414），主要增量在三处：一是把 Pylance 独占功能（语义高亮、inlay hints、import 建议 code action、ignore 注释 code action、Jupyter 支持）重新实现在开源语言服务器里；二是给 builtins 补 docstring（用 docify 抓取编译模块文档并打进 typeshed stub）；三是 CLI/LSP 的分发方式。与阅读直接相关的语义高亮、inlay hints 是"改进版"，call hierarchy 在本地源码中存在但文档显示它是上游 pyright 已有能力，不是 basedpyright 的新增。分发上，PyPI 包 basedpyright 1.40.2 是一个 2.0 MB 级别以上的纯 Python 通用 wheel（13,694,487 字节，约 13.7 MB），通过依赖 nodejs-wheel-binaries 拉入平台 Node 二进制（24.19.0 的 macOS arm64 wheel 约 56.0 MB，manylinux x86_64 约 61.1 MB），合计下载约 70 MB。许可证为 MIT（LICENSE.txt 保留 Microsoft Pyright 版权声明）。安装体积的解压后大小我没有拿到，属于缺口。

## py-envdetect：How clients pick the Python environment

**问题**：How Zed, Helix and Neovim configs decide interpreter/venv for Python servers (VIRTUAL_ENV, .venv in root, uv, poetry, conda, pyenv), what each server needs the client to pass (pythonPath, settings), and Zed toolchain selector.
