## ts-locals：Scope-based go-to-definition with tree-sitter locals

**问题**：How locals queries (@local.scope, @local.definition, @local.reference) resolve within one file; nvim-treesitter-refactor / nvim-treesitter locals, Helix textobjects/locals usage, Zed outline.scm and its tree-sitter-based symbol outline; accuracy limits across files.

**摘要**：tree-sitter locals 是纯语法、单文件的作用域解析：查询用固定捕获名 @local.scope / @local.definition / @local.reference（另有 @local.definition-value），运行时在一个文件内按作用域栈把引用的文本与定义配对，不做类型、导入或跨文件解析。Helix 的 rust/python locals.scm 只服务高亮，Helix 的跳转定义走 LSP；tags 引擎把 locals 与 tags 查询拼接，用于过滤被局部变量遮蔽的名字。Zed 的 outline 基于 buffer 自身的语法树生成符号大纲，其 rust/python outline.scm 在本地稀疏克隆中缺失，无法直接核对内容。跨文件导航只能靠 LSP、ctags 或 SCIP 之类索引，locals 不能替代。

1. [fact/high] locals 的固定捕获名为 @local.definition、@local.definition-value、@local.reference、@local.scope，highlight 引擎在 query.capture_names() 中按名字识别它们。  
   来源：tree-sitter/crates/highlight/src/highlight.rs:421-431
2. [fact/high] 官方文档定义 @local.scope 表示节点引入新作用域，@local.definition 表示节点包含当前作用域内定义的名字，@local.reference 表示节点的名字可能引用之前的定义；对引用，引擎按文本在包含该位置的作用域中查找同名定义，找到则两者同色。  
   来源：tree-sitter/docs/src/3-syntax-highlighting.md:178-196
3. [fact/high] 作用域默认继承（inherits=true），可用 #set! local.scope-inherits 覆盖；作用域在节点起点越过其终点时出栈。  
   来源：tree-sitter/crates/highlight/src/highlight.rs:1005-1008 与 1015-1027
4. [fact/high] tags 引擎把 locals 查询与 tags 查询拼接成同一个 Query 编译（format!("{locals_query}{tags_query}")），单次处理一段源码，因此 tags 只看见当前文件。  
   来源：tree-sitter/crates/tags/src/tags.rs:129-132
5. [fact/high] tags 的过滤规则：当 tags 模式带 #is-not? local（name_must_be_non_local）时，若名字在包含它的作用域链中被本地定义（遇到 inherits=false 的作用域即停止）则丢弃该 tag，这样局部变量不会被当成函数或类型。  
   来源：tree-sitter/crates/tags/src/tags.rs:195-196、442-460
6. [fact/medium] tags 的合法捕获只有 @definition.*、@reference.*、@doc、@name 和 @local.(scope|definition|reference)，不接受 @local.definition-value。  
   来源：tree-sitter/crates/tags/src/tags.rs:81
7. [fact/high] Helix Rust locals.scm 把 9 类节点定为作用域：function_item、struct_item、enum_item、union_item、type_item、trait_item、impl_item、closure_expression、block；注意没有 module 作用域。  
   来源：helix/runtime/queries/rust/locals.scm:1-14

**问题**：What the Rust and Python parsers emit (kinds, scope fields, signature), JSON output (--output-format=json), readtags, speed on large repos, accuracy limits (no references); GNU Global/gtags with pygments for references; how editors jump with tags.

## searchnav：Search-based navigation heuristics

**问题**：Sourcegraph search-based code navigation (how it finds definitions with regex + ctags, ranking), dumb-jump (Emacs) rules for Rust and Python, Zoekt symbol search; precision numbers if published.

**摘要**：无 LSP 的搜索式导航（search-based）本质是“文本搜索 + 正则/ctags 启发式”，没有 AST，也没有公开的精度数字。dumb-jump 用 ag/rg/grep 配合按语言的正则（Rust 的 fn/struct/trait/impl/enum/let/const 等，Python 的 def/class/赋值/lambda 赋值）找候选，再按“当前文件优先、注释行过滤、路径短者优先”排序，最后若只有一个结果就直接跳转。Sourcegraph 的 search-based 导航同样依赖 universal-ctags 建符号索引再做符号搜索，文档明确称其为启发式、需要 100% 置信时应使用 precise 导航，并称同名常见符号（如 Get）更容易出错。Zoekt 用 ctags 符号作为排序信号之一，但文档未给出权重或基准。结论：这条路线可作为 LSP 不可用时的兜底，但不能作为精确跳转的依据。

## rust-nolsp：Rust: what non-LSP navigation gets right and wrong

**问题**：Concrete analysis of tree-sitter tags/locals, ctags and an offline SCIP index (rust-analyzer scip) for Rust: same-name methods on different types, trait method dispatch, re-exports (pub use), glob imports, macro-generated items, impl blocks, modules in other files. ## py-nolsp：Python: what non-LSP navigation gets right and wrong

**问题**：Same analysis for Python: imports (from x import y, relative, __init__ re-exports), dynamic attributes, methods on self, inheritance, decorators, star imports, site-packages targets. tree-sitter tags/locals, ctags, stack-graphs Python (tree-sitter-stack-graphs-python), scip-python. **摘要**：Python 非 LSP 导航的结论：tree-sitter tags 只抓定义和调用名，不解析导入、self 或继承，纯靠名字匹配，所以只能给大纲和粗略跳转。ctags 的 python 解析器同样只记录导入的角色（role）而不做解析，它的 member 类型在本次未核实。stack-graphs 的 Python 规则（tsg）能解析的情况最多：绝对导入、相对导入（. 和 ..）、__init__.py 重导出、星号导入、self 实例属性、基类继承、super()、装饰器都有测试夹具覆盖。它的主要缺口是没有 site-packages / pip 解析（只索引给定源码目录）、builtins 为空文件、最后一次 changelog 是 2024-12，而本地 clone 最后提交是 2025-09。scip-python 不是非 LSP 方案，它是 pyright 的 fork，做类型感知的精确索引，依赖 pip/venv 与 --environment，成本远高于前三者。
