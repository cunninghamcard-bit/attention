## mygo-syntax：mygo ui/editor: syntax highlighting model

**问题**：How highlighting works (syntax.go, lexer.go, lexers.go, languages.go, highlighter tests): regex lexers or other; TokenKind set; which languages are built in (Rust? Python?); the extension point for a custom highlighter (could tree-sitter or semantic tokens plug in?).

**摘要**：mygo ui/editor 的高亮是手写的逐行词法器（非正则），内置 33 种语言，Rust 和 Python 都在内。Token 是固定的 25 种 TokenKind 枚举，主题只按这套枚举上色。扩展点是 Language.Highlighter 函数字段，可以接入自定义的解析器式高亮器（如 tree-sitter），接口是 Edit / Highlight(budget) / Tokens，并可选实现 SyntaxSelector、Folder、BracketMatcher、Indenter。mygo 本身不依赖 tree-sitter，只在注释和测试桩里提到它；editor 包里也没有 semantic tokens 的支持。因此 LSP 的 semantic tokens 要接入，需要自己把它映射到这 25 种 kind 上，或者自己实现 Highlighter。

## mygo-editor：mygo ui/editor: read-only mode, folding, find, scale

**问题**：Read-only support, folding (fold.go), find (find.go), line backgrounds/gutter, multicursor, diff view; buffer data structure (buffer.go) and large-file performance from bench_test.go; public API surface (doc.go) a host uses.

**摘要**：mygo v0.7.5 的 ui/editor 包是一个“编辑器 + diff 查看器”，只绘制可见行。只读是 State.ReadOnly 的一个开关：文本可选中、可复制，但编辑类命令和编辑入口都被拦截，查找替换也被隐藏。折叠是 State 上的 Fold/Unfold/FoldImports/Folded，默认由缩进、括号和 import 段推导，语言可通过 Folder 接口覆盖。查找（finder）支持大小写、整词、正则、限定选区，并在编辑后只重搜变动行。行背景、文本背景、gutter 标记和 DiffBase 修改条都由 State 的选项提供。大文件性能靠 4096 字节分块的持久 rope、按行惰性布局和每帧 4ms 的语法高亮预算实现，但 bench_test.go 只定义了 10 万行文件的基准，模块里没有记录的 ns/op 数字，本次也未运行。多光标在 multicursor.go 中实现，没有找到显式的光标数上限。

## acard-async：Acard main-thread model for async language work

**问题**：How native plugins do background work and return to the UI thread (shellapi.Update / shellapi.OnMain, RFC §5.8), cancellation via plugin context; examples in existing plugins; per-frame cost rules. What an LSP client loop must follow.

**摘要**：任务前提需要修正：仓库里已经没有 shellapi 包。RFC 0001 §10.1 第 3 条记录，2026-11-02 已删除全部 `*api` 单例包（shellapi 等），现在的 API 是 `*shell.Shell` 的 `sh.Update(fn)` 和 `shell.OnMain(ctx, sh, fn)`，而且 grep 结果也证实没有 shellapi 引用。线程模型是：UI 状态只在 mygo 主线程修改；后台 goroutine 的结果用 `sh.Update` 投递回主线程并重绘；命令处理函数需要拿回结果时用 `shell.OnMain`，它不能在主线程上调用。取消靠插件 ctx：每个 `ctx.Go` 任务必须在 ctx 取消时返回，卸载会先等这些任务结束再执行 Effect。每次发起请求时用 `context.WithCancel(s.ctx)` 保存 cancel，新请求到来就 cancel 旧的，并用 seq 计数丢弃过期结果（search、outline、filetree、textdoc 都是这个模式）。每帧成本的规则是：View 里不做磁盘读写和服务调用（RFC §5.8、native/AGENTS.md），重解析放到 Generation 变化时再做。LSP 客户端的循环现在没有现成实现，下面是我根据这些规则推断出的要求。
