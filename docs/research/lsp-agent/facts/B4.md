## zed-agent：Zed agent panel and threads

**问题**：Zed agent panel: threads, thread history storage, profiles, tool permissions, "follow the agent" (agent moves the editor), adding context (files, selections, symbols), multiple concurrent threads. Facts from docs.

**摘要**：Zed 原生 agent 面板（Zed Agent）以“线程”为单位运行，线程之间彼此独立（各自的 agent、上下文窗口、对话历史），可同时运行多个线程。Threads Sidebar 按项目分组展示线程，线程切换器可快速循环切换。线程历史分两层：归档后可在 Thread History 中恢复，永久删除则不可恢复。“跟随 agent”是面板左下角的十字准星按钮，开启后编辑器会跳到 agent 读写的每个文件。上下文通过消息输入框中的 @ 添加（文件、目录、符号、历史线程、skills、diagnostics、分支 diff、URL），也可把编辑器或终端中的选区加入线程。配置档（profile）只决定工具“是否可用”，工具权限（tool permissions）才决定调用时“允许、拒绝或确认”，两者是分开的机制。文档没有说明线程历史在磁盘上的存储格式与位置，本地 sparse checkout 中也没有 agent 相关 crate，无法核实。

1. [fact/high] 每个 Zed Agent 线程拥有独立的 agent、上下文窗口和对话历史，可同时运行多个线程；Threads Sidebar 按项目分组显示。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/agent-panel.md (Managing Multiple Threads); ~/Projects/lsp-ref/zed/docs/src/ai/parallel-agents.md (Running Multiple Threads, Threads Sidebar)
2. [fact/high] 线程切换器快捷键 agents_sidebar::ToggleThreadSwitcher 可循环切换最近线程，按住 Shift 反向切换，且在面板和侧边栏中都可用。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/parallel-agents.md (Switching Threads)
3. [fact/high] 归档的线程进入 Thread History，可恢复；运行中的线程必须结束后才能归档。永久删除会移除会话历史及关联的 worktree 数据，且无法恢复。Thread History 支持按线程标题模糊搜索。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/parallel-agents.md (Thread History, 第 36-44 行)
4. [fact/high] Thread History 跨所有项目按时间排序，可通过侧边栏底部时钟图标或 agents_sidebar::ToggleThreadHistory 打开。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/parallel-agents.md:38; ~/Projects/lsp-ref/zed/docs/src/ai/agent-panel.md:52
5. [fact/high] “跟随 agent”通过面板左下角的十字准星图标开启，编辑器会跳到 agent 读写的每个文件；提交消息时按住 cmd/ctrl 也可自动跟随。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/agent-panel.md (Following the Agent)
6. [fact/high] agent 生成期间发送的消息默认排队，待 agent 结束后发送；对 Zed Agent 可开启 Steer，使其在下一步（通常是工具调用与回复之间）插入；外部 agent 不支持 Steer，因为 Zed 无法检测其轮次边界。  
   来源：~/Projects/lsp-ref/zed/docs/src/ai/agent-panel.md (Queueing Messages)
7. [fact/high] 上下文通过消息输入框中的 @ 添加，可引用文件、目录、符号、历史线程、skills、diagnostics、分支 diff 和待抓取的 URL；多行代码粘贴会自动转为带文件上下文的 @ 提及，agent::PasteRaw 可粘贴原文。

8. [fact/high] 编辑器或终端中的选区可通过 agent::AddSelectionToThread 快捷键、动作或 + 菜单中的 Selection 项加入线程作为上下文。

9. [fact/high] 内置配置档（profile）有三个：Write（读、编辑、运行命令）、Ask（只读的代码库问答）、Minimal（不使用项目工具）。配置档存放在 settings 的 agent.profiles 下，可设置默认模型、内置工具与 MCP 工具的可用性。

## parallel-agents：Parallel agent apps and worktree-per-agent UX

**问题**：Facts on UIs that run many agents in parallel: Conductor (conductor.build), Crystal (stravu/crystal), Vibe Kanban, Sculptor, Cursor background agents, Claude Code desktop multiple sessions. How each isolates work (git worktrees), shows status, reviews diffs.

## approval-ui：Approval and permission UI patterns in GUI clients

**问题**：How GUI agent clients present tool approvals: Zed tool permissions (always allow, per tool), Claude desktop/Code permission modes, Alma approval UI, dim questions; inline vs modal, batching, remembered decisions.

**摘要**：GUI 智能体客户端的审批通常是：每次工具调用给出 允许一次 / 始终允许 / 拒绝 / 拒绝并说明原因 四种决定，并把"记住"的范围收窄到具体工具、命令模式或会话（而非全局）。Zed 用三态 confirm/allow/deny 加 always_allow/always_deny 正则规则，"Always for <tool>"是工具级、"Always for <pattern>"仅在能提取安全模式时才生效，优先级由内置安全规则到全局默认逐级排列。Claude Code 提供 default/acceptEdits/plan/auto/dontAsk/bypassPermissions 六种模式，"Yes, and don't ask again"按工具定时间范围（Bash 按仓库加命令永久、文件修改到会话结束）并写入 .claude/settings.local.json。Alma 在聊天内联卡片给出四个动作，同时有全局 toolApprovalDialog 队列，allow_always 按线程加命令或工具键记录。dim 协议层 ApprovalDecision 仅 Allow/Deny，"记住"靠 ADR 012 的会话路径授权（仍为 Proposed），而 ADR 003 提议把审批范围限定为模型工具调用。批处理（一次审批多个调用）在所查来源中均未找到明确证据。
