# RFC 0003：窗口布局和组件改为 Arc 式

- 状态：草案，讨论中（§9 待确认）
- 日期：2026-11-02
- 范围：`native/ui`、`native/plugins/{layout,workspace,slots,appearance,project,commandpalette,switcher,filetree,outline,backlinks,bookmarks}`
- 关联文档：[RFC 0001 §5.12](0001-go-native-plugin-browser.md) · [RFC 0002](0002-crychic-ui.md) · [产品线规划](../product.md) · [外观系统](../appearance.md)

---

## 1. 目标

RFC 0001 §5.12 已经决定视觉不再对照 Obsidian，但窗口骨架和组件画法仍然是 Obsidian 的：

- 窗口骨架：最左一列图标栏，左右两个 dock，每个分屏顶上一条横排标签栏，带面包屑的标题栏，底部状态栏，还有「No file is open」空白页。
- 组件画法：到处 1px 边框，灰底按层加深，选中项是一块更深的灰。

这份 RFC 把这两层都换成 Arc 浏览器的做法，同时落实 [product.md](../product.md) 阶段二的设计：一个标签是一个文件，项目是文件的属性，项目以旁侧列的形式呈现。

## 2. 已定的决定（2026-11-02）

1. 窗口结构和组件画法都改成完整的 Arc 式，不做折中版。
2. 一个标签就是一个文件，项目是它的属性。文件树、大纲、反向链接合成右侧一栏，跟随当前标签变化。
3. 每个项目有自己的颜色。标签行上显示这个颜色，窗口底色跟着当前标签所属的项目变。
4. 引入标签文件夹。
5. 保留分屏，删掉底部状态栏。

**窗口**

- 窗口底色由主题的 `surface` 加上当前项目颜色混合得到（见 §5）。
- 左侧栏和右侧上下文栏都直接画在这层底色上，不画边框。
- 正文是一张内容卡片：底色是 `background`，四周留 `spacing`，圆角放大，用阴影和底色区分，不画边框。
- 分屏时是几张卡片并排，卡片之间留一道缝。

**左侧栏：标签**。宽度可以拖动，可以整体收起。从上到下：

1. 顶行：窗口控制按钮的留位、收起侧栏、后退、前进。后退和前进作用于当前标签。
2. 地址栏：显示当前标签的地址。
   - 本地文件显示 `项目/目录/文件`，网页显示 URL，只读文件前面加一把锁。
   - 点击后打开 Omnibox。
   - 标签类型的 `Header`、`Actions` 和 ⋯ 菜单都画在这里。网页标签的地址输入框和建议弹出层直接放进这个位置。
3. 主体：一次显示一个面板，默认是标签面板（见 §4）。另外两个面板是搜索和 webview 面板。
4. 状态行：当前标签类型的 `Status`，比如光标位置、语言，缩成一行灰色小字。
5. 底栏：设置齿轮和各面板的切换按钮。

**右侧上下文栏**：跟随当前标签，可以整体收起。从上到下三段，每段都能折叠：

1. 项目：当前标签所属项目的文件树。
   - 默认只展开当前文件所在的那一层；
   - 顶部显示项目名和颜色；
   - 网页这类不属于任何项目的标签，这一段改成列出已挂载的项目。
2. 大纲。
3. 反向链接。

**Omnibox**：沿用命令面板的机制，新增一个合并模式，同时搜文件、网址和网页建议、命令。

- `Ctrl T`（新标签页）和 `Ctrl L`（地址栏）打开的就是它。
- `Ctrl O` 只搜文件，`Ctrl P` 只搜命令，这两个保留。

**起始页**：替代空白页。中间是 Omnibox 的输入框，下面是最近打开的文件和各个项目。

## 4. 标签、项目和文件夹

**项目是标签的属性。** 一个标签的项目，就是它的文件所在的那个挂载目录。

- 终端标签按工作目录判断项目。
- 网页标签没有项目。
- 不同项目的标签混在同一个列表里，每一行用项目颜色的圆点区分。

**工作区的数据模型要改。** 现在是 Obsidian 的模型：一棵分屏树，每个分屏有自己的一组标签。竖排标签列表放不下这种模型，所以改成 Arc 的模型：

- 侧栏里是一个列表，每一项是三种之一：
  - 标签；
  - 分屏：两到四个标签并排显示，在列表里占一行，标题写成「A | B」；
  - 文件夹：装着若干标签或分屏，可以折叠，可以重命名。
- 点击列表里的一项，内容区就显示它：一个标签显示一张卡片，一个分屏显示几张并排的卡片。
- 把一个标签拖到内容卡片的边上，会和当前标签合成一个分屏。从分屏里拖出去就拆开。
- `session.json` 改成存这个列表；读到旧格式时，每个旧分屏组转成一个分屏项。

**文件夹的其余规则见 §9 问题 1–3。**

## 5. 组件视觉

`native/ui` 里的每个组件都按以下规则重画。主题文件的格式不变（还是 9 个界面色和 9 个语法色），只改 `build.go` 推导其余颜色的规则。

| 项 | 现在 | 改成 |
|---|---|---|
| 边框 | 菜单、输入框、对话框、各栏之间都有 1px 边框 | 去掉。层次靠阴影和半透明叠加来分 |
| 悬停 | `surface` 往 `text` 方向混 6% | 叠一层半透明白，暗色主题叠半透明黑 |
| 选中 | 更深的灰 | `background` 色的浮起卡片，带细阴影 |
| 行高 | 28 | 34 |
| 圆角 | 6 | 行和输入框 8，卡片 10，弹层 12 |
| 弹层（菜单、下拉、Omnibox、对话框、地址建议） | 实色背景加边框 | `glass.go` 的 `Frost` 毛玻璃，带阴影 |
| 输入框 | 带边框 | 半透明填充，无边框，获得焦点时显示强调色的环 |
| 主按钮 | 强调色方块 | 强调色圆角胶囊 |
| 次按钮 | 带边框 | 半透明填充 |

**项目颜色**

- 每个挂载目录有一个颜色。默认从 8 种预设色里按项目名取，可以在项目右键菜单和设置里改。
- 颜色存在项目配置里，在 `Mount` 上加一个 `Color` 字段。
- 窗口底色是 `surface` 往项目颜色混合，亮色主题约 12%，暗色约 18%。切换标签时底色带过渡动画。
- 没有项目的标签用主题原本的 `surface`。

**要新增的组件**：

- 侧栏标签行（`TabRow`）；
- 文件夹行；
- 分屏行；
- 地址栏；
- 内容卡片；
- Omnibox 的大输入框和结果行。

**要删掉的组件**：`TabChip`，因为横排标签栏不存在了。

## 6. 每个扩展点放在哪

| 现在 | 改成 |
|---|---|
| 图标栏：快速切换、命令面板 | 合并进 Omnibox |
| 图标栏：终端、网页 | Omnibox 里的命令，以及起始页的入口 |
| 图标栏：设置 | 左侧栏底栏的齿轮 |
| 左 dock：文件 | 右侧上下文栏的「项目」段 |
| 左 dock：搜索、webview 面板 | 左侧栏面板 |
| 左 dock：书签 | 见 §9 问题 3 |
| 右 dock：大纲、反向链接 | 右侧上下文栏的两段 |
| 横排标签栏 | 删除，由左侧栏的标签列表替代 |
| 标题栏：后退、前进 | 左侧栏顶行 |
| 标题栏：面包屑、`Header`、`Actions`、⋯ 菜单 | 地址栏 |
| 状态栏：挂载名 | 删除，地址栏和上下文栏都显示了项目 |
| 状态栏：`Status`、Read-only | `Status` 进左侧栏状态行，Read-only 变成地址栏的锁 |
| 空白页 | 起始页 |

## 7. 接口变化

- **`slots`**
  - 删除 `RibbonItem`、`StatusItem`；
  - `Dock` 改成两个位置：`Sidebar`（左侧栏的面板）和 `Context`（右侧上下文栏的段）；
  - `Context` 段多一个默认是否折叠的属性。
- **`workspace`**
  - 数据模型从分屏树改成列表（见 §4）；
  - 对外的 `OpenResource`、`OpenTab`、标签类型的契约不变。
- **`project`**：`Mount` 加 `Color`；新增「哪个项目包含这个路径」的查询。
- **设置**：删除 `showRibbon`、`showTabBar`、`showViewHeader`，读到旧值就忽略。
- **文档**
  - `native/AGENTS.md`：「Port behaviour from the TS app」改成只管行为，窗口结构和组件画法以本 RFC 为准；
  - RFC 0001 §5.12：补一句指向本 RFC；
  - product.md 阶段二：形态 A、B、C 定为 A，起始页和 Omnibox 指向本 RFC。

## 8. 分步实施

每一步单独提交，每一步都能运行，都要过 gofmt、vet、测试、asl 和 CLI 端到端测试，再截图核对。

1. `native/ui` 按 §5 重画现有组件，`build.go` 改推导规则。
2. `layout`：画成左侧栏、内容卡片、右侧上下文栏，删掉图标栏和状态栏；`slots` 改成 `Sidebar` 和 `Context` 两个位置。
3. `workspace`：数据模型改成列表；加上标签面板、地址栏和状态行；迁移 `session.json`。
4. 项目颜色、上下文栏的三段（文件树跟随当前标签）。
5. 标签文件夹。
6. Omnibox 合并模式和起始页。
7. 清掉作废的设置项和接口，以及 Obsidian 文案（`No file is open`、`vault` 等），同步改各份文档。

## 9. 待确认

1. **文件夹怎么建。**
   - 推荐：手动建，像 Arc 那样把标签拖进去。另外提供一个「按项目整理」命令，一次性把现有标签按项目分进各自的文件夹。
   - 另一种：按项目自动成组，每个项目一个文件夹，不能手动调整。
2. **要不要分固定区和普通区（Arc 的 Pinned 和 Today）。**
   - 推荐：分。文件夹只出现在固定区；固定区的标签关掉只是卸载，条目还留在列表里，下次点开重新加载。普通区的标签关掉就没了。
   - 另一种：不分。文件夹里的标签关掉也就没了，文件夹只起分组作用。
3. **书签怎么办。**
   - 推荐：并进固定区。书签就是固定的标签，书签分组就是文件夹，书签面板删掉；现有的 `bookmarks.json` 迁移成固定区的内容，`bookmark` CLI 命令照旧，改为读写固定区。
   - 另一种：书签保留成一个独立面板，和固定区是两回事。
